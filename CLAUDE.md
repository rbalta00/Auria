## Project overview

"Auria" — a single-page static site selling gold-plated jewelry (oro laminado) with WhatsApp-based ordering and home delivery (Puebla, MX), plus a separate password-protected admin panel for tracking orders in Supabase. There is no build step, no framework, and no package.json — every page is a self-contained HTML file with inline `<style>`/`<script>`.

## Files

- `index.html` — the storefront: hero, delivery policy, product catalog (filterable by category, paginated client-side), FAQ, footer. All product data and all interactivity is inline vanilla JS at the bottom of the file. **Includes Meta Pixel (ID: 1543346170662334) for event tracking** (PageView, ViewContent, AddToCart, Lead).
- `admin.html` — internal order-tracking panel (`noindex, nofollow`), gated by Supabase Auth email/password login (`sb.auth.signInWithPassword`), not by any repo-level secret.
- `publisher.html` — **Social media publisher** (Jul 27, 2026): tool for creating and scheduling product posts to Facebook. Loads products from `catalogo.json`, generates captions with WhatsApp links, stores drafts in localStorage. Useful for keeping the Auria Facebook page active with jewelry product photos.
- `garantia.html`, `privacidad.html` — static policy pages linked from the footer.
- `catalogo.json` — the product catalog consumed by `index.html` and `publisher.html` via `fetch("catalogo.json")` at load. Each product: `{ id, code, name, price, category, image }`. `CATEGORY_MAP` in `index.html` groups raw `category` values (e.g. `HUGGIES`, `ARRACADAS`) into the user-facing filter tabs (`Aretes`, `Pulseras`, `Dijes`, `Cadenas`, `Juegos`, `Anillos`).
- `catalogo.txt`, `pagetext/*.txt`, the catalog PDF — raw source material the current `catalogo.json` was extracted from; gitignored, kept locally only as a reference for re-extracting/updating products.
- `mensajes-whatsapp-business.txt`, `textos-capcut-ads.txt` — copy templates for WhatsApp Business quick-replies and ad scripts; not consumed by any code, just reference text for the business owner.
- `PIXEL_SETUP.md` — setup guide for Meta Pixel configuration (reference documentation).

## Architecture

### Storefront ordering flow (`index.html`)

- Products render into `#product-grid` from the in-memory `ALL_PRODUCTS` array (loaded from `catalogo.json`), paginated 16 at a time (`visibleCount`/`PAGE_SIZE`) and filterable via `currentFilter` / `CATEGORY_ORDER`.
- There is no cart or backend order model — "ordering" means building a `wa.me` deep link with a pre-filled message (`waLink` for a single product, `waLinkMulti` for a multi-item message with computed total) and opening it in a new tab. `WHATSAPP_NUMBER` is hardcoded at the top of the script.
- `selectedProducts` (in-memory, not persisted) backs a max-3-item "selection" flow: adding from the lightbox or clicking "Pedir por WhatsApp" on a card both push into `selectedProducts`; the floating `#seen-bar` reflects it and its own WhatsApp button uses `waLinkMulti`.
- `openProductFromURL()` supports deep-linking to a single product via `?p=<code>` (case-insensitive match against `catalogo.json`'s `code` field) — scrolls to the catalog, opens that product's lightbox, and auto-adds it to the selection. Used for sharing a specific piece outside the site.

### Admin panel (`admin.html`)

- Talks directly to a **different** Supabase project than the invitaciones-XV business (`SUPABASE_URL`/`SUPABASE_ANON_KEY` are hardcoded inline, distinct project from other repos in this account).
- Access control is Supabase Auth (real login), not a shared secret in the URL/code — do not assume this page is safe to expose the way an unauthenticated static page would be.
- Order folios follow `AUR-MMDD-###`, generated by `nextFolio()` which queries existing folios for today's date prefix (`ilike("folio", "AUR-MMDD-%")`) and increments the trailing counter — keep this scheme if adding new order-creation paths so folios stay sortable/unique per day.

## Updating the catalog

To add/change products, edit `catalogo.json` directly (or regenerate it from a new PDF export via the gitignored `pagetext/`/`catalogo.txt` extraction files) — there's no CMS or admin UI for catalog editing, only for order tracking.

### Runbook: user says "ya subí/guardé las fotos nuevas" (2026-11-08)

Established workflow: the user drops raw new jewelry photos (generic `WhatsApp Image ...jpeg` filenames, straight from her phone — no code/price/category encoded in the filename) into `fotos-nuevas-sin-procesar/`, then just tells Claude "ya las subí" in a later session — expects Claude to do everything else. Do this:

1. List `fotos-nuevas-sin-procesar/` — anything new there is a candidate to add.
2. **Product name/price/category can't be inferred from a raw photo.** If the user hasn't already given this info in the same message (or via an updated `catalogo.txt`/PDF export), ask for it per batch (a simple list is enough: "foto 1 = Huggies corazón rodio, $230, HUGGIES" etc.) — don't guess prices or invent names.
3. Rename/move each processed photo into `assets/catalogo/`, following the existing convention: lowercase `aur-NNN.jpg`, `NNN` = next sequential number after the current max in `catalogo.json` (currently 197 products, `aur-001.jpg`..`aur-197.jpg` roughly — check the real max before assigning).
4. Add one entry per product to `catalogo.json`: `{ id: "pNNN", category, name, price, tag, image: "assets/catalogo/aur-NNN.jpg", code: "AUR-NNN" }` (match `id`/`code` numbering to the image's `NNN`; `category` must be one of the raw values `CATEGORY_MAP` in `index.html` already groups — check that file if introducing a genuinely new category).
5. If the user says to remove/discontinue products, delete their `catalogo.json` entry and move the photo file to `duplicados-removidos/` (don't just delete the photo outright — this folder is the existing "soft trash" convention) — don't guess which to remove, she names them or says "borra las que ya no tengo" and lists which.
6. Move the now-processed source photos out of `fotos-nuevas-sin-procesar/` (into `assets/catalogo/` per step 3 — nothing should linger in the inbox folder once handled).
7. Commit + push to `main` (see "Publicar cambios" below) -- this single push auto-deploys Auria AND (once the multi-brand setup below exists) every other branded storefront that reads this same shared catalog, with no extra steps.

## Inventario compartido entre Auria y Universo de Joyas (agregado 2026-11-09)

`admin.html` tiene una tarjeta nueva "📦 Inventario" (buscador + lista de las 197 piezas
del catalogo con un campo de stock editable, boton "💾 Guardar"). Vive en una tabla nueva
**`inventario_joyeria`** en el MISMO proyecto Supabase que ya usan los referidos
(`npllotjcjplpdztbxhla`, cuenta `inforbventas1-prog`, cliente `sbRef` ya existente en este
archivo) -- a proposito el MISMO proyecto que usa `karla`/Universo de Joyas para
`pedidos_karla`, porque las dos marcas venden la MISMA pieza fisica (mismo catalogo,
mismo proveedor) -- el stock tiene que ser uno solo, compartido, o se puede vender dos
veces la misma pieza desde las dos tiendas.

- Esquema: `codigo` (PK, mismo valor que `catalogo.json`'s `code`, ej. `AUR-047`), `stock`
  (integer), `actualizado_en`. RLS abierta a `anon` (select/insert/update), mismo modelo
  de seguridad que el resto del proyecto.
- **El stock arranca en 0 para TODAS las piezas a proposito** -- no se inventaron
  cantidades reales (no existian en ningun lado). Isaac/la vendedora tiene que capturar
  las cantidades reales desde cualquiera de los dos paneles de admin.
- Al crear un pedido desde `admin.html` (aqui o en Karla), se descuenta automaticamente 1
  unidad del stock por cada pieza con `code` no vacio en el pedido (`descontarInventario()`,
  llamada despues de un insert exitoso en `pedidos`/`pedidos_karla`). No bloquea la venta
  si el stock ya esta en 0 o negativo -- solo informa, para no trabar una venta real por un
  numero que todavia no se ha capturado bien.
- Probado en vivo: guardar un stock desde el panel de Auria y confirmar que aparece igual
  en el panel de Universo de Joyas (y viceversa), usando los mismos 197 productos de
  `catalogo.json`.
