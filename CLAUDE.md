# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

"Auria" — a single-page static site selling gold-plated jewelry (oro laminado) with WhatsApp-based ordering and home delivery (Puebla, MX), plus a separate password-protected admin panel for tracking orders in Supabase. There is no build step, no framework, and no package.json — every page is a self-contained HTML file with inline `<style>`/`<script>`.

## Files

- `index.html` — the storefront: hero, delivery policy, product catalog (filterable by category, paginated client-side), FAQ, footer. All product data and all interactivity is inline vanilla JS at the bottom of the file.
- `admin.html` — internal order-tracking panel (`noindex, nofollow`), gated by Supabase Auth email/password login (`sb.auth.signInWithPassword`), not by any repo-level secret.
- `garantia.html`, `privacidad.html` — static policy pages linked from the footer.
- `catalogo.json` — the product catalog consumed by `index.html` via `fetch("catalogo.json")` at load. Each product: `{ id, code, name, price, category, image }`. `CATEGORY_MAP` in `index.html` groups raw `category` values (e.g. `HUGGIES`, `ARRACADAS`) into the user-facing filter tabs (`Aretes`, `Pulseras`, `Dijes`, `Cadenas`, `Juegos`, `Anillos`).
- `catalogo.txt`, `pagetext/*.txt`, the catalog PDF — raw source material the current `catalogo.json` was extracted from; gitignored, kept locally only as a reference for re-extracting/updating products.
- `mensajes-whatsapp-business.txt`, `textos-capcut-ads.txt` — copy templates for WhatsApp Business quick-replies and ad scripts; not consumed by any code, just reference text for the business owner.

## Architecture

### Storefront ordering flow (`index.html`)

- Products render into `#product-grid` from the in-memory `ALL_PRODUCTS` array (loaded from `catalogo.json`), paginated 16 at a time (`visibleCount`/`PAGE_SIZE`) and filterable via `currentFilter` / `CATEGORY_ORDER`.
- There is no cart or backend order model — "ordering" means building a `wa.me` deep link with a pre-filled message (`waLink` for a single product, `waLinkMulti` for a multi-item message with computed total) and opening it in a new tab. `WHATSAPP_NUMBER` is hardcoded at the top of the script.
- `selectedProducts` (in-memory, not persisted) backs a max-3-item "selection" flow: adding from the lightbox or clicking "Pedir por WhatsApp" on a card both push into `selectedProducts`; the floating `#seen-bar` reflects it and its own WhatsApp button uses `waLinkMulti`.
- `openProductFromURL()` supports deep-linking to a single product via `?p=<code>` (case-insensitive match against `catalogo.json`'s `code` field) — scrolls to the catalog, opens that product's lightbox, and auto-adds it to the selection. Used for sharing a specific piece outside the site.

### Admin panel (`admin.html`)

- Talks directly to a **different** Supabase project than the invitaciones-XV business (`SUPABASE_URL`/`SUPABASE_ANON_KEY` are hardcoded inline, distinct project from other repos in this account).
- Access control is Supabase Auth (real login), not a shared secret in the URL/code — do not assume this page is safe to expose the way an unauthenticated static page would be.
- Order folios follow `AUR-MMDD-###`, generated by `nextFolio()` which queries existing folios for today's date prefix (`ilike("folio", "AUR-MMDD-%")`) and increments the trailing counter — keep this scheme if adding new order-creation paths so folios stay sortable/unique per day.

## Updating the catalog

To add/change products, edit `catalogo.json` directly (or regenerate it from a new PDF export via the gitignored `pagetext/`/`catalogo.txt` extraction files) — there's no CMS or admin UI for catalog editing, only for order tracking.
